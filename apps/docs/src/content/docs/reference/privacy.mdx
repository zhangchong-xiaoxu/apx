APX runs on your computer and keeps your chats, agents, files and keys there. This fork sends no telemetry by default.
Only an explicit `APX_TELEMETRY` sink enables reporting. The sections below describe what that configured sink receives.

## With a configured sink: installation steps

Under a random id made for this alone (it is not your home id, your name or anything about your computer), APX sends
each of these once, when it happens:

| Step | When |
|---|---|
| Installed | The core starts for the first time. |
| Opened | The panel opens for the first time. |
| Answer on statistics | You answer the question below (again if you change it). |
| Setup finished | You finish the first-run setup. |
| First use | You send your first message. |
| Updated | APX starts on a new version. |

Each one carries the APX version, the operating system (`darwin`, `linux`, `win32`), the processor (`arm64`, `x64`)
and how APX was installed (desktop app, install script or source checkout). The time is stamped by the receiving
server, not by your computer.

## Only if you say yes: usage numbers

The setup asks, with the box unticked: **Share anonymous usage statistics**. An install from before this question asks
once in the corner of the window. If you say yes, APX sends one report a day, starting the day after:

- tokens in and tokens out, summed over every model and provider;
- how many turns your agents ran;
- how many projects, agents, channels and routines you have.

Only these numbers. You can change your answer any time in **Settings › Advanced › Usage statistics**, which also shows
the next report's numbers and the last thing sent, exactly as it left.

## Never sent

Your messages or anything an agent wrote; names of people, agents, projects or files; folder paths; which models or
providers you use; API keys, tokens or secrets; your home id; your IP address on purpose (the receiving service sees
it to answer the request, as any web request does, and APX does not store it).

## The Chrome extension

The APX extension for Chrome shows this APX in Chrome's side panel, and lets APX's agents work in the tabs of its
**APX** tab group. The extension itself collects nothing: it makes no network requests of its own, stores nothing and
has no analytics. The panel is APX's own screen, served from `127.0.0.1` on your computer, so what you type there is
handled by APX as in the app: kept on your computer, and sent only to the model providers you set up in APX to answer
it.

It reads and acts on a web page only in a tab of the **APX** group, only when an agent works there for something you
wrote in the side panel. What it reads goes to APX on your computer through Chrome's native messaging (never over the
network), and from there, like any page an agent reads, to the model provider answering. Tabs outside that group are
never read. The extension adds nothing to the reports above.

## Where it goes

There is no default receiving service. `APX_TELEMETRY=https://example.com/telemetry` sends JSON to that endpoint;
`APX_TELEMETRY=firestore:your-project` writes to the selected Google Cloud Firestore project through its REST API.
The owner of that service controls its location, access rules and retention. This fork does not configure or deploy
an upstream telemetry project.

## Turning it off

<Aside>
Any of these stops everything, including the install steps: `APX_TELEMETRY=off` in the core's environment or
`core.env`, `DO_NOT_TRACK=1` ([Console Do Not Track](https://consoledonottrack.com)), or a `CI` variable.
</Aside>

To start over with a new random id, delete `telemetry-id` in your APX home (`~/.apx/v2`). If you explicitly configured
a sink, contact its operator to remove any records, using the telemetry id shown in Settings › Advanced.
